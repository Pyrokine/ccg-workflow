# 多 Agent 协同

## 启用条件

默认由主会话直接完成，新增 Agent 数量为 0，文件数、步骤数和耗时本身不触发派发

用户明确要求协作，或独立责任有明确收益时再安排 Agent；普通事实查询、单文件读取、连续调用链、同一模块修改和已有有效验证证据由主会话直接处理

| 条件           | 依据                         | 处理                             |
| -------------- | ---------------------------- | -------------------------------- |
| 工作独立       | 各范围无需频繁共享状态       | 按文件所有权委派有界任务         |
| 材料隔离       | 大量中间材料与主会话结论无关 | 委派独立调查，返回判断和必要证据 |
| 工具或权限隔离 | 子任务有独立环境或权限范围   | 保持实际权限检查，按已有授权派发 |
| 独立验证       | 高风险发现需要另一份证据     | 限定待验证主张和预算             |
| 用户要求团队   | 用户指定协作方式             | 在指定总量和边界内安排           |

普通有界工作使用宿主 Agent，确需持续通信与协作时使用 Team 能力；已决定派发后再选择角色和工具

派发前明确独立范围、Agent 总量、最大深度、token 或时间预算、停止条件、去重键和输出格式；约束不完整时由主会话继续处理

常规 subagent 为叶子节点，新增责任交给主会话协调；第二层 reviewer／verifier 仅按主会话预先限定的工作项与总量安排

## 宿主动作与权限

| 协同动作   | Codex 工具    | 约束                             |
| ---------- | ------------- | -------------------------------- |
| 创建子任务 | `spawn_agent` | 按已定义预算和范围派发           |
| 下发或追问 | `send_input`  | 传递改变下一动作的必要信息       |
| 等待完成   | `wait`        | 复用活动任务，按宿主完成事件等待 |
| 只读探索   | `explorer`    | 按分配范围调查并提供证据         |
| 执行改动   | `worker`      | 仅写分配文件，保持叶子角色       |
| 回收任务   | `close_agent` | 按宿主协议处理已结束的子 Agent   |

Claude Code 使用当前宿主提供的 Agent、Team、SendMessage 和等待工具，参数以实际 schema 为准；Workflow 按宿主实际 schema
传递当前要求和角色限制，返回后核对最新 authority，保持脚本原有输入合同

只读规划优先由主会话检索，Agent 名称与角色保持原有会话绑定和权限检查，其他 session 的任务保持认领及内容隔离

## 任务分配与文件所有权

每个文件在同一时刻只有一个写入者，按独立文件组或模块分配，依赖任务等待前置输出就绪

每个 dispatch 包含工作目录、当前 task ID 与 revision、文件范围、目标、完整当前 requirements、匹配角色的精确 spec、验收条件与预算

分析、规划和 reviewer 保持只读，Worker 只修改分配文件，`.ccg/` 生命周期由主会话通过控制器管理

共享文件需要串行修改；必须扩大写范围时向主会话说明具体文件和效果，由主会话判断，不通过角色名称放宽权限

## 通信与状态

派发使用宿主真实工具参数；完成时返回文件、结果、决定性证据与尚未验证项，发现影响其他所有者下一动作的冲突或阻塞时及时说明

状态按宿主任务工具维护为 pending、in_progress、completed 或可表达的阻塞状态；完成记录按当前任务约定清理，持久任务状态使用
CCG 控制器

## 失败与恢复

子任务失败时读取实际错误，区分可恢复原因、权限缺口和方案变化，再决定重试或调整方法，独立工作继续执行

等待超时时复用现有活动任务和宿主等待机制，保留超时或未知状态；确认原写入者已停止写入后再转移文件所有权

外部结果返回后重新 resolve，消费当前 requirements、精确 spec、nextAction 与 Gate，保持失败及未完成状态

## 集中验收与交付

整批修改完成后汇总适用质量关卡与相关测试，同一候选的多个触发条件合并；复现所需的定向检查保留

复用候选、输入、工具链、参数、配置和覆盖仍适用的证据；修复后只复验影响项，独立检查继续完成，失败、超时和未完成分别保留

主会话回到当前源码与调用者确认 finding，原责任者持续处理已授权范围内的问题；独立复核按真实变化和风险安排，满足验收标准后结束

默认交付未提交的修改和实际验证结果；用户要求提交时由主会话按项目规范提交指定文件，推送和发布分别遵循实际授权

## 叶子任务模板

```text
目标：{独立责任}
工作目录：{workdir}
当前任务：{task-id 与 revision}
写范围：{owned_files}
当前要求与精确规范：{requirements 与 spec sections}
验收条件：{acceptance}
预算：{总量、最大深度、token 或时间上限}
停止条件：{stop condition}
去重键：{deduplication key}
返回格式：{结果、文件、证据、未验证项}
保持叶子角色，新增责任交给主会话协调；需要扩大写范围时报告具体影响
```
